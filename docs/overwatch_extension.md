# 오버워치 확장 시나리오

> 이 문서는 구현이 아니라 구상입니다. PUBG 프로젝트에서 만든 방식(정제 → 품질 점검 → 독립 신호 → 검토 후보)을 오버워치 내부 로그에 적용한다면 어떻게 할지 정리했습니다.

## 1. 왜 PUBG로 시작했나

처음에는 오버워치 데이터로 하려고 했지만 두 가지 이유로 PUBG로 바꿨습니다.

- 오버워치는 매치 단위 데이터를 주는 공식 공개 API가 없습니다.
- 비공식 경로로 볼 수 있는 프로필 통계도 플레이어가 프로필을 비공개로 하면 볼 수 없어서, 표본이 공개 설정한 사람으로 치우칩니다.

PUBG는 공식 API로 매치 단위 참가자 통계를 받을 수 있어서, 같은 문제(슈터 게임의 이상 행동 후보 찾기)를 실제 데이터로 먼저 풀어볼 수 있었습니다.

## 2. PUBG에서 배운 것 중 그대로 가져갈 것

| PUBG에서 확인한 것 | 오버워치에 적용 |
|---|---|
| 봇이 참가자의 39%였고, 빼지 않으면 분포가 왜곡됨 | 연습 상대 AI, 사용자 지정 게임, 아케이드를 먼저 분리 |
| 훈련장·튜토리얼 매치가 참가자 0~1명 매치의 원인 | 매치 종류(빠른 대전/경쟁전/사용자 지정)를 스키마에 반드시 저장 |
| 킬 1~2개면 헤드샷 비율이 0% 또는 100%로 튐 | 명중률·치명타 비율은 최소 발사 수/처치 수 조건을 둠 |
| 분당 피해량과 킬 수는 상관 0.66으로 사실상 같은 신호 | 신호를 고를 때 서로 상관을 먼저 확인하고 독립적인 축만 조합 |
| 교전이 없던 매치는 매치 내 z-score가 튐 | 같은 매치 비교 + 전체 기준 하한을 함께 사용 |

## 3. 오버워치에서 다른 점

- **영웅마다 정상 범위가 다릅니다.** 위도우메이커의 치명타 비율과 라인하르트의 치명타 비율은 비교할 수 없습니다. 그래서 비교 단위는 "같은 매치"가 아니라 **"같은 영웅 + 같은 경쟁전 구간(티어)"** 이어야 합니다.
- **팀 구성이 고정(5:5, 역할 고정)입니다.** PUBG처럼 roster 인원이 가변적인 문제는 적지만, 역할(돌격/공격/지원)별로 지표를 나눠 봐야 합니다.
- **같은 플레이어가 계속 나옵니다.** PUBG `/samples`는 무작위 매치라 한 사람이 최대 3판만 나왔지만, 내부 로그라면 계정 단위로 시간 흐름에 따른 변화(갑자기 실력이 오르는 구간)를 볼 수 있습니다.

## 4. 부정행위 유형별 로그 신호 가설

> 플레이어로서의 경험을 바탕으로 세운 가설이며, 실제 로그로 검증해야 합니다.

| 유형 | 의심 신호 | 정상 플레이와 헷갈리는 경우 |
|---|---|---|
| 에임봇 | 히트스캔 영웅(위도우메이커, 캐서디, 솔저: 76, 애쉬 등)의 치명타 비율이 같은 영웅·티어 분포에서 극단값, 시야 밖에서 들어온 적에게 반응하는 시간이 비정상적으로 짧음 | 원챔 장인, 상위 티어 플레이어 |
| 트리거봇 | 조준선이 적에게 닿은 순간과 발사 사이의 간격이 매번 거의 같음 (사람은 흔들림이 있음) | 매우 숙련된 플레이어도 간격이 짧지만 분산은 있음 |
| 월핵 | 벽 너머 적을 향해 시점을 돌리는 빈도, 정보 없이 적 위치로 먼저 이동하는 비율 | 소리 정보, 팀원 콜, 맵 숙련도 |
| 대리 게임/계정 공유 | 같은 계정에서 주 영웅, 명중률, 접속 시간대가 갑자기 바뀜 | 새 영웅 연습, 실력 향상 |

PUBG 프로젝트에서 쓴 "독립 신호 2축(교전량 + 정확도)" 구조를 그대로 확장해, 위 신호 중 서로 상관이 낮은 것들을 조합하고 여러 개에 동시에 걸린 경우를 우선 검토 대상으로 둡니다.

## 5. 한계

- 위 신호 대부분(반응 시간, 시점 이동)은 매치 요약 통계가 아니라 **텔레메트리(프레임 단위 이벤트 로그)** 가 있어야 계산할 수 있습니다. PUBG 프로젝트는 매치 요약 통계만 써서 이 부분은 검증하지 못했습니다.
- 통계 신호는 "확인할 대상을 좁히는" 역할입니다. 최종 판단은 리플레이 확인이나 클라이언트 탐지 같은 다른 근거와 함께 해야 오탐으로 정상 플레이어를 제재하는 일을 막을 수 있습니다.
